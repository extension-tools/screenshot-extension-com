How to add text to a screenshot

To add text to a screenshot, open the saved image in an editor, choose the Text tool (T), create a text box, and type your label. Adjust its appearance and position, then save a new copy. Use Paint on Windows or Preview’s Markup tools on Mac for a native route.

Choose the right text action

Text overlays are new labels placed over an image. They are useful for instructions, feedback and explaining an error, but they are different from recognizing or replacing letters already in the capture.

Your task Action to look for What it does
Add “Select this button” or another visible note Text or annotation control Places a new label on the screenshot
Copy an error message into a ticket OCR or text-recognition control Recognizes existing characters so you can copy them
Correct wording in the actual interface Edit the source app or document, then recapture Produces a screenshot of the corrected source

For feedback, leave the captured UI intact and put your comment beside it. This lets the recipient distinguish what the interface currently says from what you want changed. A control named Text Actions may refer to recognition rather than a label tool; check what it does before proceeding.

How to add text to a screenshot on Windows

Open the image in Paint and create a label

Start with a saved screenshot. You can also paste a copied capture into Paint with Ctrl + V, then follow the same annotation steps. Pasting the picture and adding a written label are separate actions.

  1. Preserve the original. Duplicate the file in File Explorer or plan to save the annotated result under a new name. For example, keep checkout-error.png and create checkout-error-notes.png.
  2. Open the image in Paint. Right-click the screenshot and choose Open with → Paint, or open it from inside Paint.
  3. Choose the Text tool. Look for Text or the T control. Its location can vary by Paint version.
  4. Click the image to create a text box. Place it in a clear area near the detail you want to explain.
  5. Type a short label. For example: “Move this button below the error message.” Keep the instruction specific enough that the recipient knows what to do.
  6. Format the active label. Use the available controls for font, font size and color. Choose a readable style and high contrast with the area behind the lettering.
  7. Position and proofread it. Adjust the active box so the words fit and do not cover the evidence. Check spelling, line breaks and the target of the instruction before saving.
  8. Save your image as a new PNG copy. Use File → Save as, select PNG and choose the filename and folder. Reopen the saved copy to confirm that the label is visible and legible.

Microsoft’s Paint documentation describes creating a label with the Text control and customizing its appearance. Avoid assuming that every version has the same toolbar layout or active-object behavior.

The saved PNG is a picture containing your annotation. Do not assume that reopening it will give you a separately selectable label. Preserve an editable version only if the app provides a supported way to do so, and keep the unannotated source regardless.

Add text on Mac with Preview

Preview can annotate an existing screenshot without requiring a separate screenshot editor. Duplicate the source first because saving an annotated image has an important editability boundary.

  1. Duplicate the screenshot in Finder. Select the file and choose File → Duplicate, then give the copy a useful name.
  2. Open the duplicate in Preview. If another app opens by default, Control-click it and choose Open With → Preview.
  3. Show the Markup toolbar if it is hidden.
  4. Choose Text. Enter your words in the new text box.
  5. Drag the box into position. Keep it close to the relevant detail while leaving the original message or button label visible.
  6. Use Text Style to adjust the label. Choose the available font, style, font size and color controls. Check that the lettering is readable against the screenshot.
  7. Review the wording and placement before saving. Apple states that after you save an annotated image, you cannot edit, move or delete its annotations. Make corrections now; your untouched original remains the fallback for another version.
  8. Save your image copy and reopen it. Confirm that the new text appears where you intended and is readable at the size you expect the recipient to use.

These steps and the save boundary are documented in Apple’s Preview image annotation guide. Reopening the saved image is a check of the result, not a way to recover its separate annotation objects.

If you frequently need to revise labels after closing a file, choose a workflow that explicitly supports editable annotations or project files. Do not rely on a PNG or JPEG alone to preserve that editing state.

Add a label in a compatible Chrome editor

If your installed Screenshot Extension editor includes Add image and Text, you can annotate a saved PNG or JPEG there, or use a capture already open in the Editor. These instructions apply only when those controls are present; they do not mean every published version includes this editing workflow.

  1. Open the screenshot with Add image, or select the current capture.
  2. Choose Text, place a label and type your new text.
  3. Adjust the available font size and color settings. Use high contrast and check the words against the actual background.
  4. Select and move or resize the label as needed before applying the edits.
  5. Choose Apply changes, then select PNG in the available download format control and choose Download.
  6. Open the saved output and verify the label, its position and the surrounding detail.

If your popup only downloads captures and has no editor controls, save the screenshot and use Paint or Preview. The native instructions above also work when you receive an image from someone else rather than capturing it yourself.

Make the label readable and useful

A good annotation answers the question the screenshot alone leaves open. “Wrong” identifies a complaint; “Show the error beside this field” gives the recipient a concrete next action.

Suppose a customer cannot finish a form. Keep the error message and relevant field in view, place your explanation in nearby clear space, and use an arrow if the target is ambiguous. Put longer reproduction steps in the ticket instead of covering the screenshot with a paragraph.

Choice Practical approach What to check
Wording Give one instruction or observation per label Can someone understand the requested action without guessing?
Placement Keep the note near its target, outside the evidence Are the error, control name and relevant page context still visible?
Letter size Choose a font size for the recipient’s reading scale Does it remain readable after attachment or insertion into a document?
Contrast Use high contrast between the letters and the area behind them Do the words disappear against an image or busy interface?
Background If supported, use a suitable background color or shape behind the label Does it improve readability without hiding needed content?
Direction Use arrows or callout tools where available Is it clear which control or region the note describes?

No font size works for every screenshot. A long page may shrink dramatically inside a ticket preview, while a small crop may appear much larger. Test the actual presentation rather than choosing a number and assuming it will remain legible.

If the background is too busy and your app has no label-fill control, move the note to a clear area. Another option is a shorter label with a supported arrow pointing to the detail. Do not assume every editor includes the same background or callout tools.

Keep labels visually consistent within one instruction. Several competing colors and sizes can make it harder to distinguish the sequence from the interface itself. Use emphasis for the action that matters, and leave enough space around each annotation to separate it from the captured controls.

Save a shareable copy and preserve later changes

Choose from the export formats your editor actually supports. PNG is a useful starting point for interface screenshots and sharp lettering. JPEG may suit a destination that requires it, but compression can affect fine edges. Inspect the image quality of the saved result rather than assuming one option always looks better or produces a smaller file.

Keep two things separate: the original screenshot and the annotated image you are sending. If your app supports an editable project, save that too when later revisions are likely. A raster export is not a promise of preserved text editing: the visible letters may simply be pixels in the finished image.

For a client review, use a clear name such as signup-form-label-notes.png. After attaching it, open or download the attachment once to confirm that you sent the correct version and that the label is readable. Copy and paste can be convenient, but it does not guarantee a particular saved format or retain separate annotation objects in the destination.

If a full-page capture makes the note too small, provide a focused excerpt alongside the full reference. You can crop the screenshot while retaining the title, error or control that explains its context. If the local file is sharp but the shared version looks soft, compare the files using the guide to blurry screenshots.

Common problems when adding labels

Problem What to check What to do next
You cannot type a new label You may be using OCR, selection or another editing mode Choose the Text tool and create a label area, then type your words.
Words are missing or cut off The box may be too small or partly outside the image Adjust the active box or shorten the wording, then check the saved result.
The note covers the error Placement hides the detail needed to understand the issue Move the label into clear space and use an arrow where supported.
The label becomes tiny after sharing The image may be scaled down in the destination Open the actual attachment; if needed, send a readable crop alongside the full image.
You cannot edit saved letters The image may contain flattened annotations rather than editable objects Return to an editable project if you have one, or annotate another copy of the original.
A named control is absent Your app or extension version may differ Use the available native route rather than assuming the missing feature is installed.

Before sending, read the annotation as if you had not seen the problem before. The label should explain the screenshot, and the screenshot should still provide enough evidence to support the label.

Frequently asked questions

How to add text to a screenshot without changing the original?

Duplicate the screenshot first or save the annotated result under a new filename. Open the copy, add your label and export it. Keep the unannotated file separately; if your editor supports an editable project, retain that as well for later changes.

Can I change text already in the image?

Captured letters are part of the image rather than ordinary document text. For feedback, place a new annotation beside the existing text so the original remains clear. To show a genuine correction to an interface or document, update the source and take another screenshot.

Why can’t I edit the label after saving?

A saved PNG or JPEG may contain the label as pixels rather than a separate editable object. Apple specifically states that Preview’s image annotations cannot be edited, moved or deleted after saving. Use a supported editable project for later revisions, or start again from your preserved original.

Is OCR the same as adding a label?

No. OCR recognizes characters already visible in the picture so you can copy or process them. An annotation adds a new visible explanation. Use a Text control for a label and a recognition control when you need to copy the captured words.
